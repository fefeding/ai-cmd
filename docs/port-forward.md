# SSH 端口转发 / 隧道

把本地端口与远程服务打通，最常见的用途是**访问远程内网里的数据库**（MySQL / PostgreSQL / Redis 等），
以及**把本机服务暴露给远程**（例如让公网访问本机跑的开发服务器）。

底层完全复用已经建立的 SSH 连接（ssh2 的 `forwardOut` / `forwardIn`），**不新建 SSH 连接**，
隧道随会话一起建立和销毁。

---

## 两种方向

| 方向 | 等价命令 | 监听端 | 目标端 | 典型场景 |
|---|---|---|---|---|
| `local`（本地 → 远程） | `ssh -L` | **本机** | SSH 服务器侧 | 本机数据库客户端连 `127.0.0.1:3306`，实际打到远程内网的 MySQL |
| `remote`（远程 → 本机） | `ssh -R` | SSH 服务器侧 | **本机** | 让公网通过 `服务器IP:8080` 访问本机开发服务 |

配置在「连接编辑 → 端口转发 / 隧道」里，可设置多条规则，每条可单独启用与自动启动。

规则含义：

- **监听地址 / 监听端口**：流量入口
- **目标地址 / 目标端口**：流量出口
- **自动启动**：会话建立后自动拉起该规则（默认开）

---

## 服务端要求

### 1. `GatewayPorts`（仅 `remote` 方向需要）

`remote` 方向要让**其它机器**访问到，必须让 sshd 在非回环地址上监听：

```bash
# /etc/ssh/sshd_config
GatewayPorts clientspecified
```

`GatewayPorts no`（很多发行版的默认值）会强制把远程转发绑回 `127.0.0.1`，
即使客户端请求 `0.0.0.0` 也不例外。此时外部访问会直接超时。

改完 `sudo systemctl reload ssh` 生效。

### 2. `MaxSessions`（强烈建议调高）

OpenSSH 默认 `MaxSessions 10`，限制**单条 SSH 连接上并发打开的 session 通道数**。
端口转发的**每一个 TCP 连接都要占一个通道**，浏览器对同一域名会保持 6 条并发连接
（HTTP/1.1 每域名上限），再加上终端 shell、SFTP、后台 exec 采集通道，
默认值很容易被打满 —— 表现就是页面资源大面积 `net::ERR_` 失败、加载十几秒。

```bash
# /etc/ssh/sshd_config
MaxSessions 100
```

`sudo systemctl reload ssh` 生效。

### 3. 防火墙 / 安全组

`remote` 方向对外暴露端口时，记得放行云厂商安全组与主机防火墙（`ufw`/`firewalld`）。

## 性能建议

- **自己本机调试不需要隧道**：直接访问 `http://127.0.0.1:<port>`。
  走 `remote` 隧道意味着浏览器的**每一个字节**都要穿过 SSH，
  受 `MaxSessions`、SSH 通道窗口和公网往返延迟三重约束。
- **`local` 方向对浏览器更友好**：浏览器连的是本机监听端口，
  只有「目标端」那一段走隧道。
- 隧道已默认关闭 Nagle 算法（`setNoDelay`），并对连接本机目标设置了 10s 超时，
  目标不可达时快速失败而不是长时间挂起。

## 排错

| 现象 | 原因 |
|---|---|
| 远端端口没监听 | 规则没启动；检查隧道面板状态，或会话建立后手动启动 |
| 远端只监听 `127.0.0.1` | `GatewayPorts` 未开启 |
| 外部访问超时 | `GatewayPorts` 未开启，或安全组未放行 |
| 页面资源大量 `net::ERR_` / 加载很慢 | 服务端 `MaxSessions` 已满，调高后 reload |
| 隧道状态显示错误 | 隧道面板会显示具体错误信息（端口占用、目标不可达等） |

隧道面板会显示每条规则的运行状态与**活跃连接数**，可用于判断通道是否被占满。

## API

| 端点 | 说明 |
|---|---|
| `POST /api/tunnel/list` | 列出某会话下所有规则的运行状态 |
| `POST /api/tunnel/start` | 启动指定规则（幂等） |
| `POST /api/tunnel/stop` | 停止指定规则 |
| `POST /api/tunnel/stopAll` | 停止某会话的全部隧道 |
